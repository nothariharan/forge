Designing architecture ideas that set the lab apart.
The Robin material is useful because it tells you what judges will attack: rediscovery, hallucinated refs, "plausible slop", and unmeasured speedups. So I'd build the architecture around answering those, and the floor makes each answer visible. Here's what I'd put in, ranked by value per hour:

Pre-registered predictions + a surprise score (the core idea). Before any experiment runs, the hypothesis agent must commit a prediction and a falsification criterion to the ledger, hashed and timestamped. After the run, surprise = how far the result diverged from the prediction. That number triggers the alarm, the whiteboard wipe, and the replan. It makes "results change the next decision" a measurable mechanism instead of a vibe, and almost no hackathon team will do it.
Info-gain planner with a budget. Keep a belief per hypothesis and pick the experiment with the best expected learning per unit cost (compute, time). The brief explicitly asks for the planner to choose between competing tests under a budget. Log every choice with its numbers, so the demo can say "it picked test B over A because 2.3x expected learning per dollar".
Citation verifier as an Omnigent policy. Any handoff that carries a claim with a reference gets denied unless every reference resolves (DOI/arXiv ID via OpenAlex or arXiv API) and the cited text supports the claim. That's real policy-as-code, which is what the 30% orchestration score wants. It's also a direct answer to Robin's 44.5% hallucinated refs in the o4-mini ablation.
Novelty referee (red-team agent). Every hypothesis gets checked against prior art and labeled NOVEL / KNOWN / CONTRADICTED before compute is spent on it. This is the answer to the ripasudil rediscovery criticism. If your top finding turns out to be KNOWN, say so on screen. That's rigor, and it scores better than hiding it. On the floor it's a "peer review" room where the referee agent argues against the whiteboard agent.
Built-in bench mode: harness vs single agent. lab bench runs the same question through (a) one plain agent and (b) the full lab, then reports hypotheses tested per hour, hallucinated-ref rate, cost, and hit rate. That's your measured speedup with a denominator, and it copies Robin's most defensible move (harness architecture beating base model capability). Report whatever you get, 1.5x included.
Multi-trajectory consensus on analysis. Robin ran 8 independent analysis trajectories and kept what most of them agreed on. Run 3 to 5 independent analyst agents in parallel (a natural fit for Omnigent's parallel runs) and only accept results they agree on. Disagreement shows up on the floor as agents arguing at the whiteboard. It's cheap and it's a strong rigor signal.
Tamper-evident ledger + replay. Hash-chain the events (each entry includes the previous hash), store code, data version and seed per experiment, and add a "reproduce this result" command. This covers the reconstructability requirement and doubles as your demo fallback.
If time gets tight, cut in this order: 7, 6, 4. Don't cut 1, 2, 3 or 5, since they're the core of orchestration, learning and measured acceleration.

The OpenML/arXiv domain makes all of this practical: experiments take seconds to minutes, so the lab can run dozens of loops and the bench numbers actually mean something. A slow domain would starve the planner and the bench.
